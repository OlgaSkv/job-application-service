# Reports Directory

This directory stores all job processing outputs generated by the system.

## Structure

After running `process_jobs.py`, you'll see:

```
reports/
├── YYYY-MM-DD/                                    # Date-based folders
│   ├── summary_YYYYMMDD_HHMMSS.csv               # Summary with all jobs
│   ├── batch_stats_YYYYMMDD_HHMMSS.json          # Batch processing statistics
│   └── jobs/                                      # Individual job reports
│       └── JOB-UID/                               # One folder per job
│           ├── JOB-UID_parsed_jd.json            # JD Parser output
│           ├── JOB-UID_eligibility_report.json   # Eligibility Checker output
│           ├── JOB-UID_ats_score.json            # ATS Scorer output
│           ├── JOB-UID_flat_report.json          # Flattened key-value pairs
│           └── JOB-UID_full_state.json           # Complete workflow state
└── README.md                                      # This file
```

## Output Files

### Summary CSV
- **Purpose**: Overview of all processed jobs for human review and decision-making
- **Key Columns**: 
  - `job_uid`, `date_saved`, `company`, `role`, `job_url`
  - `ats_total_score`, `ats_category`
  - `eligible`, `hard_blockers`, `soft_blockers`
  - `skills_for_ats`, `strengths`, `technical_gaps`
  - `decision` (empty - you fill this with "APPLY" or "PASS")
  - `errors` (any processing errors)
  - Clickable JSON links: `parsed_jd_json`, `eligibility_report_json`, `ats_score_json`, `flat_report_json`, `full_state_json`
- **Usage**: 
  1. Review ATS scores and eligibility
  2. Click JSON links for detailed analysis
  3. Add "APPLY" or "PASS" in `decision` column
  4. Run `finalize_decisions.py` to upload approved jobs

### Batch Statistics JSON
- **Purpose**: Processing metrics for the batch run
- **Contains**: Total jobs, success/failure counts, processing time, errors

### Individual Job Reports

#### 1. Parsed JD (`*_parsed_jd.json`)
- **Purpose**: Structured job description data from JD Parser agent
- **Schema**: See `config/schemas/jd_record_schema.json`
- **Contains**: Company, role, skills (required/preferred), education, work model, clearance, years experience, domain knowledge, etc.

#### 2. Eligibility Report (`*_eligibility_report.json`)
- **Purpose**: Rule-based eligibility assessment
- **Contains**: Eligible status (true/false), hard blockers, soft blockers, commute distance, notes

#### 3. ATS Score (`*_ats_score.json`)
- **Purpose**: Detailed 30-point resume-to-JD alignment scoring
- **Schema**: See `config/schemas/ats_score_schema.json`
- **Contains**: 
  - Overall: `ats_total_score` (0-30), `ats_category` (Pass/Borderline/Reject)
  - Dimensional scores with rationales (8 dimensions)
  - Summary, strengths, technical gaps, ATS keywords

#### 4. Flat Report (`*_flat_report.json`)
- **Purpose**: Easy-to-read flattened view of all data
- **Format**: Simple key-value pairs from all workflow outputs
- **Usage**: Quick scanning without nested JSON structure

#### 5. Full State (`*_full_state.json`)
- **Purpose**: Complete workflow state with all intermediate data
- **Contains**: All inputs, outputs, errors, processing metadata
- **Usage**: Debugging, audit trail, complete record

## Note

**This folder is excluded from git tracking** (see `.gitignore`). Your actual processing results will not be committed to the repository, keeping your data private.

To see example outputs, run:
```powershell
python scripts/process_jobs.py --limit 1
```
